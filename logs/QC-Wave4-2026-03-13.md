### 2.3 SimulationEngine phase ordering
**ISSUE FOUND AND FIXED.** Required ordering per spec:
`Weather → Environment → Biology → Health → Events → Market → Finance → Tutorial → Analytics`

**Before fix:** Phase 4 was `MarketSimulation.AdvanceDays(1)`, Phase 4.5 was `Time.AdvanceDays(1)` (Storyteller). This meant Events fired *after* Market — market prices advanced with no knowledge of events fired that day. Event-driven shocks (oversupply-crash, chile-collapse, etc.) would not affect the market until the *next* day's tick.

**After fix:** Phase 4 is now Events (`Time.AdvanceDays(1)`), Phase 5 is Market (`MarketSimulation.AdvanceDays(1)`). Consequence handlers in `HandleStorytellerEvent` call `MarketSimulation.ApplyExternalShock()` which sets supply/demand indices; these are now consumed by `MarketSimulation.AdvanceDays` on the same day tick. The class-level docstring was also updated to reflect the correct 8-phase ordering.

## 3. Bugs Fixed

### BUG-001: SimulationEngine — Events phase runs after Market (logic ordering error)
**File:** `src/LakskongenSim/Core/SimulationEngine.cs`
**Severity:** High — market price shocks from storyteller events (oversupply-crash, chile-collapse, price-spike-china, etc.) were applied to supply/demand indices *after* `MarketSimulation.AdvanceDays(1)` already ran for that day. The shock would only take effect the *following* day's market tick. This means event-driven market volatility was always one day late.
**Fix:** Moved `Time.AdvanceDays(1)` (Storyteller pulse) from old Phase 4.5 to new Phase 4, before `MarketSimulation.AdvanceDays(1)` (now Phase 5). Renumbered all subsequent phases (Sustainability→6, Tutorial→7, Analytics→8). Updated class-level docstring to match.

### BUG-002: SimulationEngine — class docstring missing Events/Tutorial/Analytics phases
**File:** `src/LakskongenSim/Core/SimulationEngine.cs`
**Severity:** Low (documentation error, misleading for developers)
**Fix:** Updated `/// <summary>` docstring from `"Weather → Environment/Water → Biology/Growth → Health/Disease → Market → Finance"` to the full 8-phase spec: `"Weather → Environment → Biology → Health → Events → Market → Finance → Tutorial → Analytics"`.

### BUG-003: IntegratedDiseaseSystem — `new Random()` created per call in EstimateZoneDistance
**File:** `src/LakskongenSim/Health/IntegratedDiseaseSystem.cs`
**Severity:** Medium — `EstimateZoneDistance()` is called once per zone-pair per medium-fidelity disease update tick. Creating `new Random()` on each call risks seed collisions (on fast hardware, multiple calls within the same millisecond return identical seeds → identical "random" distances, producing deterministic and biased disease spread patterns). Also wastes allocations.
**Fix:** Added `private readonly Random _rng = new();` class field. `EstimateZoneDistance` now uses `_rng.NextDouble()`.

### BUG-004: GameBridge — `LoadGame` missing Tutorial.OnStepCompleted signal wiring
**File:** `godot/scripts/autoload/GameBridge.cs`
**Severity:** High — `StartNewGame` correctly wires `SimulationEngine.Tutorial.OnStepCompleted` to emit the Godot `TutorialStepCompleted` signal. `LoadGame` called `SimulationEngine.Initialize()` but never wired the same event handler. Consequence: tutorial progress signals never fired for players loading a saved game — tutorial UI would be frozen and no step rewards would be granted on load.
**Fix:** Added identical event hook in `LoadGame` immediately after `Initialize()`.

## 4. Notes (Not Fixed — Tracked for Future Sprints)

### NOTE-001: AchievementSystem never wired in SimulationEngine
`AchievementSystem` is a fully-built class in Core with 50+ achievement definitions. It is never instantiated or called from `SimulationEngine`. `CheckAchievements()` never runs. This is not a compile error but the system is entirely inert. Recommend adding as a wired subsystem in a future sprint.

### NOTE-002: SustainabilityManager scoring uses placeholder values
Several `CalculateXxxScore()` methods use hardcoded placeholder floats (sea lice `avgLicePerFish = 0.3`, feed sustainability `0.7f`, carbon `0.5f`, etc.) with TODO comments pointing to integration with `SeaLiceModel`, `FeedSystem`, and `LogisticsManager`. The system compiles and runs but scores reflect defaults rather than live state. Flagged for Wave 5 integration.

### NOTE-003: NorwegianEvents Equipment/Community/Competitor/Investor categories are stubs
`RegisterEquipmentEvents`, `RegisterCommunityEvents`, `RegisterCompetitorEvents`, `RegisterInvestorEvents` are all empty `{ /* TODO */ }` methods. The categories are registered but no events populate them. No bug, but the event pool is shallower than designed. Flagged for content sprint.

### NOTE-004: IntegratedDiseaseSystem.EstimateZoneDistance is a pure placeholder
Distance between zones is still random rather than derived from Zone IDs or coordinates. Medium-fidelity disease spread is therefore non-deterministic in a semantically incorrect way. Fixed the `new Random()` per-call issue (BUG-003), but a proper coordinate-based distance calculation remains needed.

### NOTE-005: TimeManager.CurrentDay vs GameState.Day off-by-one
`State.Day` increments in `Advance()` *after* `AdvanceOneDay()` completes. Inside `AdvanceOneDay()`, `Time.AdvanceDays(1)` increments `TimeManager.CurrentDay` *before* `State.Day` increments. This means `TimeManager.CurrentDay` is always 1 ahead of `GameState.Day`. The Storyteller correctly compensates by using `_state.Day + i` (which is pre-increment State.Day), so event day numbers are correct. However, any code that compares `TimeManager.CurrentDay` to `State.Day` expecting parity will be off by 1. Recommend documenting this invariant explicitly in both classes.

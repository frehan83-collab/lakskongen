**Date:** 2026-03-13

## Summary

Implemented a data-driven, 12-step tutorial and onboarding system for Lakskongen. The system guides new players from a blank game state through the full Norwegian salmon farming cycle — license acquisition, sea site setup, smolt stocking, feeding, health monitoring, delousing, harvest, P&L review, and genetics — ending in free play.

## Architecture

```
SimulationEngine
  └── TutorialSystem (new)
        ├── 12 TutorialStep objects (data-driven, inline)
        ├── CheckProgress() — called every day in Phase 6
        ├── OnStepCompleted event → GameBridge.TutorialStepCompleted signal
        └── Reads: State, SeaLice, FishPopulations (via SimulationEngine ref)

GameBridge (C# autoload)
  ├── TutorialStepCompleted signal
  ├── TutorialStepNumber, TutorialStepTitle, TutorialDescription
  ├── TutorialHint, TutorialIsComplete, TutorialCompletedCount

SimBridge (GDScript autoload)
  ├── tutorial_step_completed signal (forwarded)
  ├── tutorial_step_number, tutorial_step_title, tutorial_description
  ├── tutorial_hint, tutorial_is_complete, tutorial_completed_count

TutorialUI.gd (PanelContainer)
  ├── Reads SimBridge on every state_updated
  ├── Listens to tutorial_step_completed for animation
  └── Minimise/expand toggle via close button
```

## Design Decisions

- **C# constants, not JSON** — steps are defined inline in `BuildSteps()`. They reference live GameState/engine properties via lambdas, which cannot be represented in JSON. A JSON data file would only hold labels; the logic must live in code.

- **`Func<TutorialSystem, bool>` conditions** — TutorialSystem is passed to condition lambdas rather than GameState alone, giving conditions access to derived values (AverageFishWeightKg, SeaLicePerFish, GetStepCompletedDay) without polluting GameState.

- **Chain completion** — `CheckProgress()` loops until no more conditions fire in a single tick, preventing one-tick deadlocks when consecutive steps have instant conditions (e.g. step 11 → step 12 auto).

- **NOK rewards direct to State.Balance** — consistent with AchievementSystem pattern.

- **Time-based fallbacks** — steps 5, 6, 10, 11 use day-offset conditions rather than requiring specific UI actions the player may not have taken yet. This keeps the tutorial non-blocking.

- **TutorialUI.gd is scene-agnostic** — all node references are @export, making it drop-in for any scene. It degrades gracefully when SimBridge is absent.

---

## Integration Notes

- TutorialSystem is instantiated in `SimulationEngine.Initialize()` — it resets on every new game.
- The tutorial is **not persisted** in GameState for this iteration. On load, it restarts from step 1. Persistence can be added later via a `TutorialSaveData` DTO if needed.
- `GameBridge.LoadGame()` does not wire the tutorial event — that path starts with an existing save and tutorial can be skipped.

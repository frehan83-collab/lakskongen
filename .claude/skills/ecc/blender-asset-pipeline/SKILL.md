# blender-asset-pipeline: build Lakskongen's 3D assets the repo way

Every model in `godot/assets/models/` is generated by a Python script in
`blender/`, run by headless Blender. Nothing is modelled by hand, and nothing
is committed from an interactive session. The scripts are deterministic: the
same script writes the same `.glb` byte for byte on every run.

## 1. The pieces

| Piece | What it is |
|---|---|
| `blender/build_*.py` | One build script per kit. `build_salmon.py`, `build_pen.py` (hero pen), `build_site_kit.py` (mooring buoy, light, hose float), `build_vessels.py` (whole fleet plus ROV and AUV), `build_vegetation.py`, `build_shore_props.py`, `build_land_base.py` (F2-25 land kit), `build_offshore.py` (OF1-class). |
| `blender/*_designs.py`, `land_parts.py`, `lk_hull.py` | The geometry data each kit is built from: what goes where. |
| `blender/lk_meshkit.py` | Shared deterministic mesh kit: vector helpers and primitives, plus `strip_uv` for the trim atlas. Units are metres; Blender X right, Y forward, Z up. |
| `blender/lk_trim_atlas.py` | Trim atlas for the farm-types kits. It is one square PNG of horizontal strips (swatch along U, roughness in alpha, alpha 1.0 marks a strip that glows at night), written by a deterministic zlib writer. |
| `blender/render_*_preview.py` | Review renders: `asset` (pen and site kit), `land`, `offshore`, `vessel` (any `.glb`, plus `--fish`). They write frames only to `--out` and never into the repo. |
| `blender/asset_manifest.json` | The source of truth per asset: `type`, `scale_m`, `orientation`, `lod_levels`, `materials` (plus `lod_materials` where a LOD drops parts), `tri_budget`, `tri_max`, `export_path`, `build_script`, `build_args`, `godot_material`, `licence`. |
| `<asset>_<LOD>.json` sidecar | Written next to each `.glb` by the build. It holds `tri_count`, `material_count`, `bbox_size`, and on the richer kits per-part triangles and measured dimensions. Verification reads it. |
| `<asset>_<LOD>.glb.import` | Godot import settings. Each manifest material maps to a project `.tres` through `use_external`, and `meshes/generate_lods=false` because the LODs are made by hand. |
| `.claude/skills/ecc/blender-asset-pipeline/blender_asset_pipeline.py` | The manifest runner. `--verify-only` is the CI step. |
| `tools/blender_mcp_call.py` | Calls one Blender MCP tool from the shell (it needs Blender running with the MCP add-on). |

## 2. Build an asset (headless)

```bash
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup \
    --python blender/build_vessels.py -- --asset wellboat --lod LOD0
```

- Without `--lod`, a script builds every LOD. Without `--asset`, it builds every asset in its kit.
- Common flags:
  - `--out DIR`: write somewhere other than `godot/assets/models/...`, for example a scratch directory.
  - `--textures`: also paint the kit's textures or atlas.
  - `--no-bake`: skip ambient-occlusion baking for fast iteration (not for commits).
  - `--tri-limit-scale S`: used by tests.
- The usage line at the top of each script lists its exact flags.
- The pen, salmon, vessel, land and offshore scripts exit non-zero when a LOD goes over its triangle ceiling. The vegetation, shore-prop and site-kit scripts rely on the tests for that.
- The runner can build from the manifest instead:
  `python3 .claude/skills/ecc/blender-asset-pipeline/blender_asset_pipeline.py [--asset ID]`
  (set `BLENDER_BIN` to the Blender binary). It writes `godot/assets/asset_manifest.json` with each file's sha256, size and triangle count.

## 3. Rules every asset follows

- **Conventions:** 1 unit = 1 m. glTF export turns Blender +Z into Godot +Y, and +Y into Godot -Z, so the nose or bow is at Godot -Z. The salmon is 0.9 m from nose to tail base.
- **Determinism:**
  - No randomness, no modifiers left on export, no timestamps.
  - Any variation comes from fixed numbers in the design files.
  - Rebuild twice and compare the hashes before you commit.
- **Budgets:**
  - `tri_budget` pins the current count. Verification allows ±10 %; outside that the change was unintended or the manifest needs updating.
  - `tri_max` is the hard ceiling from the roadmap, for example pen LOD0 at or under 60k.
  - Change `tri_budget` only on purpose, in the same commit as the geometry.
- **Materials:** the material names (`LK_*`) in the export must match the manifest exactly, per LOD. Each one maps to a project `.tres` in the `.glb.import`. A new material needs a new `.tres` and an import mapping, and the asset test checks both.
- **Kit textures:** the farm-types kits use the trim atlas plus `lk_meshkit.strip_uv`, never a texture per object.
- **No real brands (D17):** a reference class may appear in a docstring (for example "Polarcirkel 500-class") but never as a logo, livery or name on the model.
- **Licences:** everything is in-house. Never import third-party meshes. Never commit the owner's reference photos; they are described in text in `docs/art/OWNER_REFERENCE_BRIEF.md`.

## 4. Check it

```bash
python3 -m pytest tests/test_salmon_asset.py tests/test_pen_asset.py \
    tests/test_vessel_assets.py tests/test_land_kit_assets.py \
    tests/test_offshore_assets.py tests/test_terrain_material.py -q
python3 .claude/skills/ecc/blender-asset-pipeline/blender_asset_pipeline.py --verify-only
```

- **Asset tests:**
  - every LOD is exported with its manifest materials;
  - triangles stay within budgets and ceilings;
  - dimensions match the spec;
  - every material has an external mapping in the import file;
  - the trim atlas and kit specifics are checked too.
  - `test_terrain_material.py` covers vegetation and shore props.
- **`--verify-only`**, the step in `tools/ci.sh` ("Blender asset pipeline verification"):
  - checks that every manifest file exists;
  - compares the sidecar's triangle count with the budget (±10 %) and the ceiling;
  - compares the sidecar's material count with the manifest;
  - checks the fish scale.
  - It records sha256 values but does not compare them against stored ones.
- Tests are add-only. Strengthen a check, never loosen it, and log any replacement in `docs/RUN_LOG.md` §7.

## 5. Look at it

- **Blender review renders** are the safe default. They run headless and write nothing into the repo:
  `Blender -b --factory-startup --python blender/render_vessel_preview.py -- --glb godot/assets/models/wellboat/wellboat_LOD0.glb --out <scratch>`
  Use `render_land_preview.py` (`--dusk` for the night strips) or `render_offshore_preview.py` (`--vessel offshore_service`) for the kits.
- **The Blender MCP** (tools `execute_blender_code`, `render_viewport_to_path`, `get_objects_summary`, …) works on the owner's open Blender. Use it for interactive look-dev and inspection:
  - try a shape;
  - inspect an exported `.glb`;
  - render a viewport.
  - Port anything worth keeping into the build script, then rebuild headless. The MCP session is never the source of a committed asset.
- **In-game checks** need a windowed Godot (`tools/capture_screenshots.sh`, visual QA). Run them only when the owner allows windowed Godot. Otherwise stay headless and leave the in-game check as a named follow-up.

## 6. Adding a new asset

1. Add the geometry to the kit's design file, or start a new `build_<kit>.py` on `lk_meshkit`.
2. Add a manifest entry with every field from §1, including `tri_max` and the `licence` line.
3. Build every LOD, then add the `.tres` materials and import mappings.
4. Extend the kit's asset test, or add one, so the new asset has the same checks as its siblings.
5. Render a review frame and compare it with the art direction in `docs/art/`.
6. Commit the `.glb`, `.glb.import`, sidecars, textures, manifest and test together.
